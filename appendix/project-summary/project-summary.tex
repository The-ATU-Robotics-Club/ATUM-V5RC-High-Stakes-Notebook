\appendix{Project Summary}
This appendix contains a summary of the project history for this team. This data
was collected from the GitHub project page for our team and lists changes to
said project page from the previous date to the date listed. The data was
fetched and added automatically every day or manually at any time.

The tabular view presented is for the convenience of the reader; for the team,
our project management tools appeared similar to a Kanban board or Gantt chart.
See \ref{fig:board-example} and \ref{fig:timeline-example} for a visual.

To avoid flooding this notebook with several dozen images of the board and
timeline, the same information is shown in a differential table view, only
showing changes overtime. This provides a complete, succinct overview of our
project history.

If a task is "Todo" or "Backlog" then the start and end dates are estimates (if
provided). If a task is "In Progress" then the start is concrete and the end is
an estimate. If a task is "Done" then both dates are concrete. Do note that tasks
in "Done" include those that may have been abandoned (these will be easily seen
by a lack of start and end date).

For reader convenience, the row colors correspond to the status of tasks:
\begin{itemize}
    \item \textcolor{gray}{Gray indicates that the task is on the backlog.}
    \item \textcolor{red}{Red indicates that the task is on the todo list.}
    \item \textcolor{yellow}{Yellow indicates that the task is being worked on.}
    \item \textcolor{green}{Green indicates the task is done (or abandoned).}
\end{itemize}

Additionally, if the assignee section is empty, that means the task is the
responsibility of the team in its entirety. Also, the person listed is the head
of that initiative, but there may be others helping (free organization GitHub
accounts do not allow multiple assignees).
